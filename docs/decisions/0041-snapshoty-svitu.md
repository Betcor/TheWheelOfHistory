# 0041. Снапшоти світу: канонічний JSON і хеш стану

- **Статус:** прийнято
- **Дата:** 2026-10-01

## Контекст

Файл світу (GD §21, етап 4) зберігає після кожного року снапшот стану, а тест реплею порівнює хеші:
`snapshot(N) + orders(N) → hash(snapshot(N + 1))`. Стан світу (`WorldState`, ADR 0040) живе в рушії, де немає Jackson
і вводу-виводу, тож серіалізація й хеш мусять бути поза рушієм і при цьому однаковими на будь-якій JVM. Карта — найбільша
частина стану (у найбільшому світі ~1,7 МБ JSON), але після генерації не змінюється.

## Рішення

- **Де.** `server/persistence`: `MapSnapshot` і `StateSnapshot` (публічні), `SnapshotWriter` / `SnapshotReader` /
  `SnapshotNode` (пакетні). Сервер отримав пряму залежність `jackson-databind` (раніше — лише транзитивно через
  `content`/`protocol`). Рушій не змінено, крім нового коду помилки.
- **Дві частини.** `MapSnapshot.of(GameMap)` — карта, пишеться у файл світу один раз. `StateSnapshot.of(state, map)` —
  усе інше, з полем `map_hash` замість геометрії; хеш стану — SHA-256 байтів знімка стану, тож через `map_hash`
  покриває й карту. Стан на іншій карті — `IllegalArgumentException` (помилка виклику, не даних).
- **Канонічний JSON** пишеться вручну потоковим `JsonGenerator`, без рефлексії й анотацій: UTF-8 без пробілів; поля — у
  сталому порядку коду; мапи стану (`TreeMap`) — масивами об'єктів з `id` у порядку ключів; відсутнє значення —
  `null`, поле є завжди; enum — ключ `snake_case` (як у контенті); ціль модифікатора — `stat:<показник>` /
  `wheel:<тип колеса>` (як у YAML); точка — `[x, y]`, многокутник — плаский масив `x0, y0, x1, y1…`; розвиненість —
  об'єкт за ключами галузей. Назви й порядок полів — формат збереження: змінюються лише з новою `schemaVersion`.
- **Читання суворе.** Дублікати ключів і зайве після кореня — помилка розбору; кожне поле обов'язкове, невідоме поле,
  не той тип, число поза `int`/`long`, невідоме значення enum, повторний id — помилка з місцем
  (`countries[3].capital`). Помилки значень з конструкторів моделі зберігають первинний код і подробиці (як у
  завантажувачі контенту). Після читання стан перевіряється `WorldInvariants`, а знімок записується знову й має
  збігтися байт у байт — неканонічний запис відхиляється, тож хеш прочитаного завжди дорівнює хешу того самого стану.
- **Помилки.** Новий код `SAVE_MALFORMED` (`SaveFileException`), подробиці: `part` (`map` / `state`), `location`,
  `problem` (для розробника: `missing_field`, `unknown_field`, `expected_int`, `not_canonical`, `map_hash_mismatch`…)
  або `cause` з подробицями первинної помилки. Версія схеми новіша за `WorldState.SCHEMA_VERSION` —
  `SaveVersionException` (`version`, `supported`); старіша — поки `SAVE_MALFORMED` (`unsupported_schema_version`),
  бо міграцій ще немає.
- **Міграції** — з першою зміною схеми: над деревом JSON до читання, у `server/persistence` (у рушії немає Jackson).
- Стискання (gzip), SQLite і `WorldStore` — наступним кроком, разом з файлом світу.

## Наслідки

- Найбільший світ (16 гравців, багато NPC): стан ~1,5 МБ JSON (~115 КБ gzip, переважно записи коліс генерації),
  карта ~1,7 МБ (~260 КБ gzip); запис стану ~8 мс, читання стану ~35 мс, читання карти ~50 мс. 200 років без
  проріджування — ~23 МБ, у межах 100 МБ файлу світу.
- Кожне нове поле стану мусить з'явитися і в записі, і в читанні; тест кругового запису на згенерованих світах ловить
  пропуск (стан після читання має дорівнювати оригіналу).
