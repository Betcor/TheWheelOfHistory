# 0024. Розмір світу

- **Статус:** прийнято
- **Дата:** 2026-09-29

## Контекст

Генерація карти (GD §3.3–3.5) починається з розміру світу: скільки держав, який шаблон карти, скільки материків і
провінцій, яка частка землі нічийна. Від кількості держав уже залежить таблиця релігій світу (ADR 0020), а далі
залежатимуть Вороной, материки й розміщення держав. GD задає формули (`NPC = гравці + колесо(2..6)`,
`провінцій = держав × колесо(60..100) × коефіцієнт шаблону`, нічийні землі — `колесо(5%..15%)`, межі ≈ 400–3500),
але не каже, як частка NPC («мало / звичайно / багато», GD §14.4) змінює формулу, що саме задає шаблон, і суперечить
одиночній грі нижньою межею «від 2 гравців».

## Рішення

- **Частка NPC — свій діапазон колеса** (рішення автора): `balance.yaml` → `world.npc_extra` — діапазон на кожну
  `NpcShare` (`few` / `normal` / `many`); NPC = гравці + результат колеса `world_npc_count` (рівні сектори
  `npc_<n>`). Держав разом — не більше 40: NPC обрізається до `40 − гравці`.
- **Гравців 1..16** (рішення автора): один гравець — одиночна гра. Межі гравців і держав — правила в коді
  (`engine/state/WorldLimits`), не баланс; верхня межа 16 лишається відкритим питанням GD §24.
- **Шаблон — коефіцієнт і діапазон материків** (рішення автора): новий файл `map.yaml` → `MapContent` з
  `MapTemplateDef` (`weight` 1..10000, `provinces_pct` 1..500, `continents` 1..12). Колесо `world_map_template` — за
  вагами в порядку контенту, далі `world_continents` — рівні сектори `continents_<n>` у межах шаблону. `MapContent`
  — окремий параметр `ContentPack`: рельєф, клімат і родовища додадуться туди ж, без зміни конструктора пакета.
- **Широкі діапазони — рівні сектори з кроком** (рішення автора): `StepRange(min, max, step)`, `max − min` мусить
  ділитися на крок (інакше `max` мовчки випав би з колеса). Провінцій на державу 60..100 з кроком 5 (9 секторів,
  `provinces_<n>`), нічийні землі 500..1500 bp з кроком 100 (11 секторів, `unclaimed_<bp>`).
- **Провінцій** = держав × провінцій на державу × коефіцієнт / 100, вниз, обрізано до `world.provinces`.
- **Хост фіксує шаблон і/або материки** (GD §3.4): зафіксоване колесо не крутиться. Якщо зафіксовано лише
  материки, колесо шаблону обирає серед шаблонів, чий діапазон їх вміщує; жоден не вміщує або зафіксований шаблон
  не дає такої кількості — `ValidationException(VALUE_OUT_OF_RANGE)`, невідомий шаблон — `UNKNOWN_REFERENCE`.
- **Колеса нейтральні:** сектори `PARTIAL`, якість 50, без переваги. Потоки `npc` / `template` / `continents` /
  `provinces` / `unclaimed` — зафіксований параметр не зсуває кидків інших коліс.
- **API:** `WorldSizeWheel.generate(rng, content, WorldSizeInput)` → `WorldSize(players, npc, template, continents,
  provincesPerCountry, provinces, unclaimedBp, rolls)`, `countries()`.

Запропоновано (чекає підтвердження автора): діапазони NPC мало 1–3 / звичайно 2–6 (GD) / багато 4–10; шаблони —
«Континенти» вага 35, ×1,0, 2–4 материки; «Пангея» 20, ×0,9, 1; «Архіпелаг» 15, ×1,2, 5–8; «Земля-подібна» 30,
×1,1, 4–6; межі провінцій 400–3500 (GD).

## Наслідки

- Кількість держав для релігій світу тепер може братися з `WorldSize.countries()`; CLI `country` поки задає її
  прапорцем `--countries` — перейде на розмір світу разом зі створенням світу.
- Нижня межа 400 провінцій для світу з 2–3 держав дає до ~150 провінцій на державу — генератор карти має
  розраховувати на це (частина стане нічийною землею або морем).
- Бюджет генерації карти (§10.8: ≤ 2 с на 3500 провінцій) не зачеплено: розмір світу — кілька обертань.
