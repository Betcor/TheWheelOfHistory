# 0047. Завантаження світу

- **Статус:** прийнято
- **Дата:** 2026-10-01

## Контекст

Після лобі (ADR 0046) світ продовжувався, лише доки його сесія відкрита: коли всі гравці пішли, файл закривався, а
відкрити його знову було нічим. Критерій етапу 4 — «збереження переноситься між режимами» (почати в LAN, продовжити на
окремому сервері, GD §21). Потрібні «Завантажити» в клієнті, сесія з файлу світу, гравці з таблиці `players` і токени
гравця, які переживають перезапуск клієнта.

## Рішення

- **Звідки світи (рішення автора):** тека сервера — вбудованого чи окремого — і список по протоколу: `ListWorlds` →
  `Worlds(WorldInfo…)` (ім'я — ім'я файлу без розширення, ключ світу, seed, рік, нікнейми гравців). Один шлях коду для
  всіх режимів; перенесення між режимами — копіювання файлу в теку іншого сервера. Список читає файли без міграції й
  без карти (`WorldStore.summary`: з'єднання SQLite лише з `query_only`; режим «лише читання» лишав поруч порожні
  `-wal`/`-shm`); пошкоджені й новіші файли пропускаються з записом у лог, відкриті сесіями — не показуються.
- **Ключ світу:** міграція `0003_world_key.sql` — `world_meta.world_key`, 16 випадкових байтів у hex
  (`WorldStore.newKey()`; наявні файли отримують ключ із `randomblob` при першому відкритті, з резервною копією, як і
  будь-яка міграція). Ім'я файлу й seed не годяться: файл перейменовують, а кілька світів бувають з одного seed. Ключ
  генерує сесія ще в лобі нового світу й передає у `WorldDirectory.create` — його отримують гравці в `Joined`.
- **Як гравці повертаються до держав (рішення автора: токен з диска, інакше хост):** клієнт зберігає номер і токен
  гравця за ключем світу (`TokenStore`, `<домашня тека>/tokens.properties`, у POSIX — `rw-------`, запис через
  тимчасовий файл; збій — лише лог). `LoadWorld(world, nickname, seat)`: з токеном свого місця хост одразу сідає на
  нього; без токена — гість лобі під нікнеймом. У лобі завантаженого світу гравці світу з державами (вільне місце — не
  на зв'язку) і гості без держави; хост віддає гостеві вільне місце (`AssignSeat(guest, seat)`): гість отримує
  `Joined` з номером місця й новим токеном, старий токен місця більше не діє, нікнейм місця — нікнейм гостя. Гравець
  світу з токеном повертається на місце через `Rejoin` — клієнт робить це сам, якщо в списку лобі ключ світу, для
  якого є токен (не підійшов — приєднується гостем). Гра починається, коли гостей без місця немає
  (`PLAYERS_UNSEATED`); гравці, яких немає, — не на зв'язку, як після від'єднання. При старті гравці переписуються у
  файл однією транзакцією (`WorldStore.updatePlayers`: нікнейм, хеш токена, хост).
- **Хто може завантажити:** без токена місця — лише клієнт того самого процесу, що й сервер (вбудований сервер через
  `LocalChannel`; `ClientSession(…, trusted)`). З мережі — і в LAN, і на окремому сервері — потрібен токен місця в
  цьому світі (`UNAUTHORIZED`): інакше будь-хто відкрив би чужий світ і роздав собі чужі держави. Перенесений на сервер
  світ відкриває той, хто в нього грав (його клієнт має токен).
- **Один файл — одна сесія:** `WorldDirectory` пам'ятає файли, відкриті сесіями (`create` і `open(name)` займають,
  `release` відпускає — у `shutdown` сесії); повторне завантаження — `WORLD_IN_USE`. Ім'я світу шукається лише серед
  файлів теки, тож шляхом (`../`) чужого файлу не відкрити (`NOT_FOUND`). Сесія займає файл у своєму потоці — у тому ж,
  де й відпускає: гонки «закрили, поки займали» немає.
- **Інший контент:** світ, створений з іншим контентом, не продовжується — новий код `SAVE_CONTENT_MISMATCH`
  (`world`, `saved`, `current`). Міграції контенту світу — окреме питання.
- **Протокол v4:** клієнт — `ListWorlds`, `LoadWorld(world, nickname, seat?)`, `AssignSeat(guest, seat)`; сервер —
  `Worlds`. `Joined` отримав ключ світу (`world`); `Lobby` і `LobbyInfo` замість seed і частки NPC — `LobbySetup`
  (`NewWorld(seed, npcShare)` / `SavedWorld(name, seed, turn)`, у JSON — `setup.kind`) і ключ світу. `Joined` без
  запиту — хост віддав місце (`SessionListener.joined`). Нові коди: `WORLD_IN_USE` (`world`), `SEAT_TAKEN`
  (`player`), `PLAYERS_UNSEATED`.
- **Клієнт:** «Завантажити» в головному меню (`LoadScreen`: світи вбудованого сервера, нікнейм, LAN), на екрані
  «Підключитися» — ще й світи сервера; лобі показує збережений світ, місця й гостей, хост віддає місце обраному гостеві.
  `GameClient.start(home, …)` — домашня тека гри (світи вбудованого сервера в `worlds`, токени поруч).

## Наслідки

- Критерій етапу 4 «збереження переноситься між режимами» виконано: `GameServerTest` грає рік у LAN (хост через
  `LocalChannel`, гість по TCP), копіює файл на інший сервер і продовжує там по TCP з токенами.
- Відновлення сесії з паузи — тепер через вихід і завантаження: файл лишається на останньому збереженому році.
  Відновлення без виходу (хостом) — окремим кроком разом із таймерами.
- Сервер з мережі не відкриває світів без токена: гравець, що втратив токени, повертається лише через хоста, який сам
  має токен. Адміністрування окремого сервера (видача місць без токена) — згодом.
- Відкрите: світ, усі гравці якого без токенів, з мережі не відкрити — лише на вбудованому сервері; «чистка» старих
  токенів на диску клієнта (зараз — один рядок на світ, без обмеження).
- Тести: `WorldStoreKeyTest`, `WorldStoreSummaryTest`, `WorldDirectoryTest` (список, зайнятість, імена), `MigratorTest`;
  `SessionActorLoadTest` (місце з токеном і продовження року, гість і роздача місць, недовірений клієнт, чужий токен,
  зайнятий і відсутній світ, інший контент, гості без місць, права й помилки роздачі, повернення в лобі й передача
  хоста, зайнятість нового файлу), `ClientSessionTest`, `GameServerTest` (перенесення LAN → окремий сервер); протокол —
  формат, читання, властивості; клієнт — `TokenStoreTest`, `GameClientTest` (місце за токеном, інший комп'ютер і гість,
  повернення в лобі завантаженого світу), `ConnectionHandlerTest`, `PlayerInputTest`, `MapScreenSmokeTest`.
